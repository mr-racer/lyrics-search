# Шаффл очереди плеера — дизайн

**Дата:** 2026-07-10
**Статус:** одобрено (реализация без отдельного implementation-плана — по решению владельца)

## Задача

Опция перетасовки очереди для обычных плейлистов: тумблер в тулбаре плеера
правее регулятора громкости. Очередь «правдива» — при включении шаффла массив
очереди физически перетасовывается с видимой FLIP-анимацией переезда строк.
Для рекомендательных очередей (волна и её производные, где следующий трек
зависит от действий пользователя) шаффл недоступен — кнопка скрыта.

## Решения (зафиксированы с пользователем)

- **Семантика:** тумблер с восстановлением. Вкл — перетасовать несыгранный
  хвост; выкл — вернуть исходный порядок хвоста.
- **Волна (`streamActive`):** кнопка полностью скрыта (не рендерится).
- **Новая очередь:** шаффл сбрасывается (`shuffleOn = false`), снапшот
  чистится. Новая очередь всегда стартует в исходном порядке. В localStorage
  ничего не сохраняется.

## Архитектура

Всё во фронтенде, один файл `frontend/src/main.jsx`. Бэкенд не трогаем.

### Состояние — в `App`, рядом с `playerPlaylist`

`App` — источник истины очереди (`playerPlaylist`) и уже умеет находить
позицию текущего трека по `playerTrack.track_id` (паттерн как в
`handleStreamSignal`). Добавляем:

- `const [shuffleOn, setShuffleOn] = useState(false)`;
- `preShuffleOrderRef` — `track_id[]`-снапшот несыгранного хвоста на момент
  включения;
- `toggleShuffle()`:
  - **Вкл:** `splitAt = indexOf(playerTrack) + 1` (сыгранные + текущий
    остаются на месте — та же блокировка, что у drag-reorder с его
    `lockedBefore`). Хвост `slice(splitAt)`: снапшот id-шников → перетасовка
    Фишера–Йетса → `setPlayerPlaylist([...head, ...shuffled])` →
    `setShuffleOn(true)`. Если текущий трек не найден (`idx === -1`),
    тасуется вся очередь.
  - **Выкл:** хвост стабильно сортируется по позиции в снапшоте. Треки,
    которых нет в снапшоте (добавлены позже: «играть следующим»,
    автоподбор), уходят в конец хвоста, сохраняя текущий взаимный порядок.
    Затем `setShuffleOn(false)`, снапшот чистится.
- **Сброс** в `handlePlayTrack` (загрузка новой очереди) и `startStream`
  (запуск волны): `setShuffleOn(false)` + очистка снапшота, без
  восстановления порядка (новая очередь всё равно перезаписывает список).

Обновлённый `playerPlaylist` доезжает до `PlayerSection` по существующему
эффекту `[initialPlaylist, initialTrack]` — новых путей синхронизации нет.

### Кнопка — в `PlayerSection`, правее `VolumeControl`

Новые пропы `PlayerSection`: `shuffleOn`, `onToggleShuffle`, `streamActive`
(пробрасываются из `App` только для `id === 'player'`, как остальные
плеерные пропы).

- В ряду иконок `player-actions-row` сразу после `<VolumeControl>` — кнопка
  `player-icon-btn` с иконкой перекрещенных стрелок (стандартный shuffle-глиф),
  `aria-pressed` и подсветка активного состояния как у кнопки «Текст песни»
  (`data-active`).
- `streamActive === true` → кнопка не рендерится.
- Один и тот же ряд иконок на десктопе и мобиле — отдельной мобильной
  обработки не нужно.

### Анимация — FLIP по строкам очереди

Строки очереди ключуются по `track_id`; на строку добавляется `data-tid`.

1. По клику на кнопку (до вызова `onToggleShuffle`) `PlayerSection` снимает
   `getBoundingClientRect()` всех строк `[data-tid]` внутри `queueScrollRef`
   в `Map<track_id, rect>` (ref).
2. После ре-рендера `useLayoutEffect` по `[playlist]` читает новые позиции и
   для каждой строки с ненулевой дельтой играет FLIP через Web Animations
   API: `translateY(dy) → 0`, ~460 мс, стаггер ~16 мс на строку (кап
   ~160 мс), в середине полёта лёгкое `scale(0.97)` — эффект тасуемой
   колоды.
3. Анимируются только строки, чья старая или новая позиция пересекает
   видимую область скролла; остальные просто оказываются на местах.
4. `prefers-reduced-motion: reduce` → снапшот не снимается, перестановка
   мгновенная.
5. Выключение шаффла играет ту же анимацию (механизм общий — capture по
   клику, анимация по факту изменения `playlist`).

## Крайние случаи

- Хвост из 0–1 трека: тумблер переключается, перестановки и анимации нет.
- Разделитель «АВТОПОДБОР» (по первому `_autoplay`-треку): при `shuffleOn`
  скрыт (треки перемешаны, граница врёт), при выключении возвращается.
- Автоподбор доклеивает треки при исчерпании очереди — встают в конец без
  повторной тасовки: шаффл — действие в момент включения, не постоянный
  режим сортировки.
- Ручной drag во время шаффла разрешён; при выключении порядок вернётся к
  снапшоту (ручные перестановки внутри шаффла не переживают восстановление —
  классическое поведение плееров).
- Стрим-сигналы (лайк/скип в волне) с шаффлом не пересекаются: в волне
  кнопка скрыта, а `startStream` сбрасывает шаффл.

## Проверка

Фронтенд без тестовой инфраструктуры (один файл, Vite) — проверка ручная +
`npm --prefix frontend run build` на синтаксис:

1. Включение: хвост тасуется с анимацией, сыгранные и текущий трек на месте.
2. Выключение: исходный порядок хвоста восстанавливается с анимацией.
3. В волне кнопки нет; после волны (новая очередь) шаффл выключен.
4. Новый плейлист сбрасывает шаффл.
5. «Играть следующим» во время шаффла: трек играет следующим; после
   выключения уходит в конец хвоста.
6. Мобильный drawer очереди: перестановка видна, ряд иконок содержит кнопку.
7. `prefers-reduced-motion`: без анимации, мгновенно.
