# Разлочка reorder «прошедших» треков очереди — дизайн

**Дата:** 2026-07-10
**Статус:** одобрено (вариант A, реализация без implementation-плана — по решению владельца)

## Проблема

Drag-reorder очереди блокирует префикс `index < currentIndex + 1` как
«уже сыгранное». При входе в альбом с середины все ранние треки считаются
прошедшими, хотя физически не слушались, — их нельзя перетащить вниз, чтобы
послушать.

## Решение (вариант A)

Закреплён **только играющий трек**. Любую другую строку — включая реально
сыгранные — можно перетащить куда угодно, в том числе через границу текущего:

- выше играющего — «зона истории», трек сам не заиграет;
- ниже играющего — будущее, заиграет в свой черёд.

Перенос сыгранного трека вниз = «переслушать» — легитимно и разрешено.

## Изменения

Один файл `frontend/src/main.jsx`, бэкенд не трогаем.

### `useQueueReorder`: `lockedBefore` (префикс) → `lockedIndex` (одна строка)

- `startSession` / `getRowProps` / `getHandleProps`: строка недоступна для
  драга, если `index === lockedIndex`; порог «есть что двигать» —
  подвижных строк ≥ 2 (`count` минус закреплённая, если она есть).
- `computeOver`: пропуск залоченного префикса убирается — слоты считаются
  по всем строкам, кроме самой перетаскиваемой. Дроп в позицию текущего
  трека разрешён (текущий сдвигается, идентичность строки сохраняется).
- Стили во время драга: закреплённая строка получает `q-locked`
  (приглушение, как раньше у префикса) **и** участвует в `q-shift`-сдвиге,
  чтобы визуальный поток строк не рвался, когда драг пересекает границу
  текущего.

### `PlayerSection`

- Вызов хука: `lockedIndex: currentIndex` вместо `lockedBefore: currentIndex + 1`.
- `reorderQueue` (commit): после сплайса `currentIndex` пересчитывается по
  `track_id` играющего трека (ref-зеркало id, как `playlistRef`) — перенос
  через границу сдвигает позицию текущего в массиве. Смена трека во время
  драга (трек кончился) не ломает пересчёт: id берётся из ref на момент
  коммита.

### Что не меняется

- Клик по строке играет её — как раньше (клики по «истории» уже работали).
- Шаффл: тасуется по-прежнему только хвост после играющего; перенесённый
  вниз трек начинает участвовать в шаффле, перенесённый вверх — нет.
- Волна: reorder и так шёл через `onReorderQueue → setPlayerPlaylist`;
  стрим-логика (`handleStreamSignal`, exclude-set) ищет по `track_id` и от
  порядка не зависит.

## Крайние случаи

- Очередь из 1–2 строк: подвижных < 2 — драг не стартует (как раньше).
- Играющий трек не в очереди (`currentIndex === -1`): закреплённых нет,
  двигается всё.
- Автосдвиг «конец трека» во время драга: коммит пересчитывает
  `currentIndex` по id из ref — позиция не расходится.

## Проверка

`npm --prefix frontend run build` + ручная: вход в альбом с середины →
ранний трек тянется вниз под текущий и играет в свой черёд; играющий трек
не тянется и приглушается во время чужого драга; перенос через границу не
сбивает подсветку/эквалайзер текущего.
