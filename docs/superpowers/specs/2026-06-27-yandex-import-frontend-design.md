# Импорт из Яндекс.Музыки — фронтенд онбординга — Design

**Дата:** 2026-06-27
**Ветка:** `feature/yandex-music-import`
**Статус:** утверждён к реализации
**Связано:** [`2026-06-21-yandex-music-import-design.md`](2026-06-21-yandex-music-import-design.md) (backend)

---

## 1. Цель

Подключить уже готовую backend-логику импорта из Яндекс.Музыки к фронтенду
первичной настройки (онбординга). Пользователь:

1. логинится в Яндекс через device-flow (вводит код на стороне Яндекса);
2. видит список своих источников («Мне нравится» + плейлисты) и выбирает **один
   или несколько**;
3. запускает импорт и наблюдает прогресс (скачивание → индексация), после чего
   попадает в плеер.

**Объём v1:** только онбординг (экран первичной настройки в server-режиме).
Доступ из Настроек для уже наполненной библиотеки — вне объёма.

---

## 2. Размещение

Импорт встраивается в существующий `ServerOnboardingScreen` (шаг «Музыка») как
**третий источник** рядом с «Выбрать папку» / «Файлы»: карточка-кнопка
**«Импорт из Яндекс.Музыки»**. Нажатие разворачивает встроенный мини-визард
`YandexImportFlow` внутри того же экрана — без новой страницы и без роутинга.

```
[ Музыка ]  →  📁 Папка | 🎵 Файлы | ▶ Яндекс.Музыка
                                        │
            ┌───────────────────────────┘
            ▼
  1. Вход в Яндекс (код + «Открыть Яндекс», поллинг статуса)
  2. Источники (мультивыбор: «Мне нравится» + плейлисты)
  3. Импорт → прогресс (скачивание → индексация) → onDone
```

Завершение вызывает тот же `onDone`, что и загрузка файлов (вход в приложение).
Поведение во время импорта — **блокирующий прогресс** (как у текущей загрузки
файлов): пользователь остаётся на экране прогресса до завершения.

## 3. Backend-правки (минимальные)

Схема БД, шифрование токена и конвейер индексации **не меняются**.

### 3.1 Мультиисточник в одной джобе

- `POST /import/yandex/start` принимает новое поле `sources: list` — каждый
  элемент это `"likes"` или `{"kind": <int>}`. Для обратной совместимости
  одиночные `source`/`kind` тоже принимаются и нормализуются в список.
- Новая функция `importer.download_sources(account_id, sources, *, on_progress)`:
  - резолвит каждый источник через `playlists.resolve_tracks`;
  - **сливает треки в один список с дедупом по `track.id`** (трек, лайкнутый и
    лежащий в плейлисте, скачивается один раз);
  - дальше — существующая логика скачивания/промоута/регистрации без изменений.
- `importer.download_source(account_id, source, ...)` сохраняется как тонкая
  обёртка `download_sources(account_id, [source], ...)` (существующие тесты
  остаются валидными).
- `LibraryService.enqueue_yandex_import` принимает `sources` (список) и передаёт
  его в раннер. Метка джобы — `<yandex:N sources>`.
- Юнит-тест: слияние двух источников с пересекающимся треком даёт один трек.

### 3.2 Передача indexing job_id фронту

В `LibraryService._run_yandex_import_job` после успешной фазы скачивания
захватываем `job_id`, возвращаемый `enqueue_upload_indexing(...)`, и включаем его
в **финальное** событие download-джобы:

```python
indexing_job_id = self.enqueue_upload_indexing(...)
await self._notify_progress(job, {
    "overall_status": IndexStatus.COMPLETED.value,
    "message": "...",
    "yandex_report": report,
    "indexing_job_id": indexing_job_id,
})
```

Это даёт фронту детерминированно переключиться с прогресса скачивания на прогресс
индексации без гонок поллинга. (Если `upload_ids` пуст — всё скачанное уже было
импортировано/всё пропущено — `indexing_job_id` отсутствует, фронт сразу
показывает итог и завершает.)

## 4. Frontend-компоненты

Всё в `frontend/src/main.jsx` (текущая структура — единый файл), рядом с
`ServerOnboardingScreen`. Используются существующие `apiFetch`, `API`, стили
`ob-glass`/`GlassCard`, i18n через флаг `ru`, компонент `Spinner`.

### 4.1 Точка входа в `ServerOnboardingScreen`

В блоке выбора источника добавляется карточка «Импорт из Яндекс.Музыки». Локальный
стейт `mode: 'pick' | 'yandex'`. При `mode==='yandex'` рендерится
`<YandexImportFlow lang isDark onDone={onDone} onBack={()=>setMode('pick')} />`
вместо upload-секции (drag-drop и список файлов скрываются).

### 4.2 `YandexImportFlow` — внутренняя стейт-машина

Шаги: `'auth' | 'sources' | 'progress'`. На монтировании проверяет
`GET /import/yandex` — если `linked:true`, стартует сразу с `'sources'`.

**Шаг `auth`:**
- `POST /import/yandex/auth/start` → `{session_id, verification_url, user_code, status}`.
- Показываем крупный `user_code` + кнопку-ссылку «Открыть Яндекс» на
  `verification_url` (target=_blank).
- Поллинг `GET /import/yandex/auth/status?session_id=` каждые ~2с:
  - `authorized` → перейти на `sources`;
  - `expired`/`error` → показать ошибку + кнопку «Попробовать снова» (рестарт).
- Поллинг останавливается при размонтировании (cleanup в useEffect).

**Шаг `sources`:**
- `GET /import/yandex/playlists` → `{sources:[{source,title,track_count,cover}]}`.
- Грид карточек с обложкой (или плейсхолдером), названием и счётчиком треков;
  «Мне нравится» первым. Чекбокс-мультивыбор (стейт `Set` выбранных).
- Кнопка «Импортировать N» (disabled при нуле). Состояния загрузки/ошибки списка
  (502/`not linked` → возврат к `auth`).

**Шаг `progress`:**
- `POST /import/yandex/start {sources:[...], lang}` → `{job_id}` (download-джоба).
- `new EventSource(`${API}/index/progress/${job_id}`)`:
  - **фаза скачивания:** из кастомных полей события (`stage:"download"`,
    `current`, `total`, `message`) рисуем бар «Скачивание X/Y» + текст message;
  - на `overall_status==='completed'`: закрываем этот EventSource, читаем
    `indexing_job_id` и `yandex_report`;
    - если `indexing_job_id` есть → монтируем существующий `MemberIndexing`
      `jobId={indexing_job_id}` (обычные бары стадий индексации → его `onDone`
      вызывает наш `onDone`);
    - иначе → показываем итог (нечего индексировать) и через паузу `onDone`;
  - на `overall_status==='failed'`: показываем `error`/`message` + «Назад».
- Под прогрессом — сводка `yandex_report` (`downloaded`, `already`, и
  раскрываемый список `skipped` с причинами), когда доступна.

### 4.3 Обработка ошибок

| Ситуация | Поведение UI |
|----------|--------------|
| 409 (импорт уже идёт) | сообщение + кнопка «Назад» |
| 502 (ошибка Яндекса) | сообщение + «Повторить» |
| `not linked` / 401 на playlists | возврат к шагу `auth` |
| device-flow `expired`/`error` | ошибка + «Попробовать снова» |

## 5. Изоляция и тестируемость

- `YandexImportFlow` — самодостаточный компонент: вход `{lang,isDark,onDone,onBack}`,
  наружу только `onDone`. Внутреннее состояние не протекает в `ServerOnboardingScreen`
  (тот лишь переключает `mode`).
- Переход «скачивание → индексация» инкапсулирован внутри шага `progress`; снаружи
  это одна непрерывная операция.
- Backend: `download_sources` тестируется юнитом (мок-клиент), `download_source`
  остаётся протестированной обёрткой. Существующие тесты импортера не ломаются.

## 6. Вне объёма (v1)

- Доступ к импорту из `SettingsPanel` после онбординга.
- Фоновый импорт с входом в приложение до завершения.
- Refresh OAuth-токена (отдельный backend-вопрос, не блокирует фронт).
- Отмена идущего импорта из UI.
