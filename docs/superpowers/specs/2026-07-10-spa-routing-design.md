# Маршрутизация SPA: кнопка «назад» + живучесть индексации — анализ и дизайн

**Дата:** 2026-07-10
**Статус:** предложение (анализ, реализация не начата)

## Проблема

Приложение — SPA без URL-состояния: `App` держит `section`
(`home | search | recommend | library | player | artist`) в `useState`,
URL никогда не меняется. Следствия:

1. Кнопка «назад» браузера выходит из приложения вместо навигации по
   разделам. В установленной PWA (standalone) это особенно больно — жест
   «назад» на Android закрывает приложение.
2. Прогресс индексации отслеживается через `EventSource`, живущий в
   локальном состоянии компонента (модалка настроек / онбординг). Ушёл со
   страницы или перезагрузил — `job_id` потерян, переподключиться не к чему,
   хотя джоб продолжает работать на сервере.
3. Обновление страницы (F5) всегда возвращает на `home`, глубоких ссылок нет.

## Что уже готово (важно: бэкенд менять не нужно)

Аудит показал, что вся серверная инфраструктура для решения уже существует:

- **SPA catch-all** в FastAPI (`app/api/main.py`, `serve_spa`) отдаёт
  `index.html` на любой не-API путь → History-API-роутинг переживает F5.
- **PWA** (`vite.config.js`): `navigateFallback: 'index.html'` +
  denylist `/api/**` → те же пути работают offline/standalone.
- **SSE `/api/v1/index/progress/{job_id}`** (`sse_utils.event_stream`)
  шлёт **полный снапшот прогресса первым событием** любому позднему
  подписчику + heartbeat-снапшоты каждые 30с → переподключение к живому
  джобу уже работает, нужен только `job_id`.
- **`GET /api/v1/library/status`** возвращает `current_job_id` / полную
  сводку прогресса для аккаунта (`LibraryService.get_status`,
  `_active_jobs` per-account) → вернувшийся клиент узнаёт о своём живом
  джобе **без localStorage**, источник истины — сервер.

Вся работа — во фронтенде (`frontend/src/main.jsx`).

## Ключевой инвариант, который нельзя сломать

Все секции рендерятся **всегда** и переключаются видимостью, а не
mount/unmount (`App`, «Render all sections; visibility toggled»). На этом
держится: непрерывность аудио при навигации, сохранение внутреннего
состояния секций (результаты поиска, скролл, вкладки библиотеки).

Отсюда главное решение: **не брать react-router** (роут-на-элемент
означает mount/unmount секций — сломает аудио и состояние; интеграция в
17k-строчный монофайл инвазивна). Вместо этого — тонкая синхронизация
существующего `section`-state с History API (~100–150 строк).

## Дизайн

### Фаза 1 — URL ↔ section (ядро, минимальный риск)

Хук `useAppRouter` на уровне `App`:

```
/            → home
/search      → search
/recommend   → recommend
/library     → library
/player      → player
/artist/:slug→ artist (+ activeArtistSlug)
```

- `navigate(section, {slug})` = `history.pushState` + существующие
  `setSection`/`setActiveArtistSlug`. Если целевой путь совпадает с
  текущим — `replaceState` (никаких дублей в истории при повторном клике).
- `popstate` → парсинг `location.pathname` → те же сеттеры. Неизвестный
  путь валидируется по списку секций, иначе `replaceState('/')` → home.
- Первый рендер: секция берётся из URL (глубокие ссылки). Deep link на
  `/player` без загруженного трека — секция уже умеет пустое состояние;
  если нет — редирект на home через `replaceState`.
- Точки интеграции минимальны: `onNav={setSection}` и `navigateToArtist`
  уже прокинуты пропсами во все секции — меняется только их реализация в
  `App`, дочерние компоненты не трогаем.
- Легаси-хэш `#login` уже вычищается в `setStoredAuth` — не конфликтует.

Бонус существующей архитектуры: скролл/состояние секций сохраняются при
back/forward автоматически, т.к. секции не размонтируются.

### Фаза 2 — живучесть индексации

1. **Единый хук `useIndexingJob(jobId)`** — владеет `EventSource`,
   отдаёт `{stageProgress, overallStatus, error}`. Сейчас логика SSE
   продублирована в 6 местах (`SettingsPanel`, `MemberIndexing`,
   `YandexImportFlow`, `UploadIndexingWizard`, `OnboardingScreen`,
   `SetupWizard`) — унифицировать инкрементально, начиная с
   `SettingsPanel` + `OnboardingScreen` (основная боль). Yandex-flow с
   handoff `indexing_job_id` оставить как есть до отдельной итерации.
2. **Резюме при загрузке**: на буте `App` (рядом с `/library/collections`)
   дёргаем `GET /library/status`; если `current_job_id` есть — поднимаем
   глобальное состояние «идёт индексация» и переподключаем SSE. Первый
   снапшот с сервера мгновенно восстанавливает все стадии — UI выглядит
   так, будто никто не уходил.
3. **Состояние живёт на уровне `App`** (или модульного синглтона), а не в
   модалке — навигация по секциям больше не убивает подписку.
4. По завершении джоба — существующий `loadCollections()`.

`job_id` в URL не нужен: он аккаунт-скоупный и восстанавливается через
`/library/status`. URL адресует только экран.

### Фаза 3 — полировка истории (опционально)

- **Мобильный полноэкранный плеер**: `openMobilePlayer` пушит запись
  истории (`state: {overlay:'player'}`), `popstate` вызывает
  `closeMobilePlayer` → жест «назад» сворачивает плеер, а не убивает PWA.
- То же для `SettingsPanel` и модалки альбома (`state: {overlay:...}`).
- Вкладка библиотеки в query (`/library?tab=liked`) через **replaceState**
  — «назад» ходит по страницам, а не по каждому клику на вкладку
  (уточнение владельца: «по страницам однозначно»); localStorage-персист
  вкладки остаётся, URL при deep link его переопределяет.

## Что НЕ делаем

- Не подключаем react-router / wouter — ломает keep-mounted инвариант,
  избыточно для 6 маршрутов.
- Не переносим `job_id` в localStorage — сервер уже источник истины.
- Не меняем бэкенд (эндпоинты, SSE, catch-all — готовы).
- Не рефакторим все 6 SSE-флоу разом — по одному, начиная с болевых.

## Риски

- `popstate` во время индексации в онбординге (`appState==='onboarding'`
  рендерится вместо `App`) — роутер должен быть no-op вне `ready`-состояния.
- Повторный `pushState` одного пути (клики по активному пункту нав-бара) —
  закрыт дедупликацией через `replaceState`.
- Vite dev-сервер: SPA-fallback включён по умолчанию (`appType: 'spa'`),
  прокси `/api` не задет.

## Порядок реализации и проверки

1. Фаза 1 → руками: навигация по всем секциям, back/forward, F5 на каждом
   пути, deep link на `/artist/:slug`, аудио не прерывается при back.
2. Фаза 2 → запустить индексацию, уйти на другую секцию, F5, вернуться:
   прогресс восстановлен; завершение обновляет коллекции.
3. Фаза 3 → Android/standalone: back сворачивает плеер, закрывает модалки,
   и только с `home` выходит из приложения.
