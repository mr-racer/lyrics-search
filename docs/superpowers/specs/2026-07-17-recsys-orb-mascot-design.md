# Шар-талисман ИИ на странице «Рекомендации» + живой прогресс агента

**Дата:** 2026-07-17 · **Ветка:** container-version
**Статус:** дизайн согласован в визуальном компаньоне (вариант Б, анимация «Вдох» / Б3);
макеты: `.superpowers/brainstorm/61-1784317389/content/orb-b-refine.html`

## Зачем

1. Сделать 3D-шар (как в чате по треку) главным талисманом ИИ: он висит над строкой
   «опиши, что хочешь услышать…» на вкладке «Рекомендации» и реагирует на работу
   playlist-агента.
2. Починить прозрачность агента: сейчас `POST /recommend/ai-playlist` возвращает
   `steps` одним куском в конце — во время запроса фронт слепой. Нужен стриминг
   промежуточных событий.
3. Бэкенд-правки качества: больше веб-запросов при бедном улове (кэп 6) и жёсткий
   fuzzy-матч (сейчас безусловно берётся `hits[0]` — много мусора).

## 1. Фронтенд: шар-талисман (вариант Б + «Вдох»)

Всё в `frontend/src/main.jsx` (страница Recommend, режим `aiOn`) + CSS в
`frontend/src/index.css`. При `aiOn === false` страница остаётся как есть
(быстрые миксы, без шара).

### Композиция

- Шар (~96–110px) заменяет `SectionHeader` («РЕКОМЕНДАЦИИ / Что включить сегодня»)
  в режиме `aiOn`; сверху отступ (~40px), не прилеплен к краю.
- Под шаром — строка-подпись (caption), ниже — радужная рамка `rec2-rim` с полем
  ввода. **Радужную анимацию рамки не трогаем.**
- Ряд чипсов `rec2-chips` (ИИ-режим) удаляется: его заменяют летающие фразы.

### Анатомия шара (в духе волны на главной)

- Жидкие блобы (4 шт., blur ~13px) под стеклянной крышкой (radial-блик + inset-тени),
  внешнее conic-кольцо (blur 4px, медленное вращение), мягкое покачивание
  вверх-вниз (`translateY`, ~4.5s). Реиспользуем грамматику `fy-*`, но отдельными
  классами (префикс `aio-`), чтобы не зацепить главную.

### Состояния

| Состояние | Палитра блобов | Кольцо | Анимация | Caption |
|---|---|---|---|---|
| `idle` | фирменная: #7c5bff / #ff78c8 / #e0b341 / #b06bff | медленное, брендовое | покачивание; фразы дрейфуют позади | серифом курсивом «что включить сегодня?» |
| `work` | холодная: #4d7dff / #6ac8ff / #8a5cff / #4dd6c2 | ярче, быстрее (~2s), синее | **«Вдох»**: 6 светящихся пылинок стягиваются в шар с разных сторон (staggered), шар «дышит» scale 1↔1.045 | бегущая shimmer-строка текущего этапа (стиль `ai-activity-current`), этапы сменяются с fade+сдвигом |
| `done` | зеленоватая: #3ecf8e / #6ee7b7 / #4dd6c2 / #34d399 | зелёное, медленное, приглушённое | покачивание | пастельно-зелёным (#c9e6d2) только результат: «15 треков» — без перечисления шагов, без жёлтого |
| `fail` | красноватая приглушённая: #e0607e / #c04b6b / #f08a8a / #a04057 | красное, тусклое | покачивание | пастельно-розовым (#e8c2cc): «ничего не нашлось — попробуй иначе» |

- `fail` = 0 треков в результате **или** ошибка запроса.
- Смена палитр — через `transition: background .8s` на блобах (как на главной, где
  вкусовые цвета «перетекают»).
- Переходы: `idle → work` при старте запроса; `work → done|fail` по финальному
  событию; `done|fail → idle` при изменении текста в поле ввода или новом запросе.
- Старая жёлтая строка `friendlySteps`-итогов в результатах удаляется (этапы теперь
  видны вживую на caption; после финала остаётся только список треков + заголовок).

### Летающие фразы-примеры

- 5–6 фраз (пул текущих `aiDemoChips` + «Хиты Канье Уеста», «песни из Watch Dogs»),
  разбросаны вокруг/позади шара, полупрозрачные (opacity .24–.36), медленный дрейф
  (translate-петли 11–16s, разные фазы).
- Шрифт: лёгкий гротеск (font-weight 300, letter-spacing .07em) — не курсивный сериф.
- **Кликабельны**: клик подставляет фразу в поле и сразу запускает запрос
  (поведение старых чипсов). Hover — opacity до ~0.7 + cursor:pointer.
- В `work/done/fail` фразы плавно гаснут (opacity → 0, pointer-events:none).

### Мобильные / доступность

- Политика «пакет C» (`@media (max-width:768px), (hover:none) and (pointer:coarse)`):
  в `idle` остаётся только покачивание шара (один дешёвый transform, как `fy-ring`);
  дрейф блобов, кольцо-анимация и дрейф фраз — заморожены (фразы видны статично).
  В `work` (короткий период) — полная анимация «Вдоха».
- `prefers-reduced-motion: reduce` — все анимации шара off, смена состояний только
  цветом.
- Существующий mobile-freeze список в `index.css` пополняется новыми классами.

## 2. Стриминг событий агента на фронт

### Транспорт

Новый эндпоинт `POST /api/v1/recommend/ai-playlist/stream` (рядом со старым; старый
остаётся для обратной совместимости и тестов). Ответ —
`StreamingResponse`, `application/x-ndjson`, по строке JSON на событие:

```json
{"type":"status","stage":"plan"}
{"type":"status","stage":"web_search","query":"Kanye West greatest hits"}
{"type":"status","stage":"matching_done","found":9,"total":14}
{"type":"result","payload":{ ...AIPlaylistResponse... }}
{"type":"error","message":"..."}        // вместо result при исключении
```

Реализация: `ai_playlist(...)` получает опциональный `on_status: Callable[[dict], None]`;
роут кладёт события в `asyncio.Queue`, генератор StreamingResponse их выкачивает,
фоновая задача выполняет `ai_playlist` и в конце кладёт `result`/`error`.
(EventSource не умеет POST — поэтому NDJSON поверх fetch-stream, а не SSE.)

### События из обоих путей

- **Путь web_hits (агент)** — уже эмитит через `state["on_status"]`:
  `filters`, `filters_done`, `web_search`, `matching`, `matching_done`.
  Пробрасываем как есть.
- **Библиотечный путь (план → действия → отбор)** — событий нет, добавить:
  `plan` (перед LLM-планом), `plan_done` (title, число действий),
  `action` (tool, query — перед каждым `_execute_action`),
  `action_done` (tool, found), `select` (candidates), `select_done` (picked).

### Фронтенд-словарь этапов (RU/EN)

`stage+поля → человеческая фраза` для shimmer-строки, например:
`plan` → «думаю над планом…», `web_search` → «ищу в интернете: „{query}“»,
`action(clap_search)` → «ищу по звучанию: „{query}“», `matching` → «сверяю с
библиотекой…», `select` → «выбираю лучшее из {candidates}». Неизвестный stage —
пропускается молча (форвард-совместимость).

`runAiPlaylist` переписывается на `fetch` + ReadableStream-парсер NDJSON
(построчный split по `\n`); каждое `status`-событие двигает caption и держит
состояние `work`; `result` → `done|fail`; сетевые ошибки → `fail`.

## 3. Бэкенд: больше веб-запросов при бедном улове

`app/services/playlist_agent/agent.py`:

- `_MAX_WEB_SEARCHES: 4 → 6`.
- В `_INSTRUCTIONS` добавить правило: если после `get_songs` в библиотеке совпало
  мало треков (< ~8) и бюджет веб-поисков не исчерпан — искать ещё, другими
  формулировками (deep cuts, «full album tracklist», другой язык запроса,
  смежные альбомы/части саундтрека), затем снова `get_songs` с новыми названиями.
  Останавливаться, когда треков достаточно (~15) или бюджет кончился.
- Сообщение «(web search limit reached…)» остаётся — модель штатно доберёт из
  того, что есть.

## 4. Бэкенд: жёсткий fuzzy-матч

`app/services/playlist_agent/resolver.py`, стадия fuzzy в `resolve_songs`:

Сейчас: безусловный `hits[0]` из `search_tracks_fuzzy` → мусорные совпадения.

Новое поведение — кандидат из top-3 BM25F-хитов принимается только если прошёл
оба фильтра, иначе `match="none"`:

1. **Похожесть названия**: `score_names(qtitle, [hit_title])` (общий
   транслит-скоринг из `app/services/name_match.py`) ≥ **0.6**. Защищает от
   «совпал один общий токен».
2. **Артист**: если у запроса известен артист (`qartist`), хит обязан пройти
   `_artist_matches` **или** `score_names(qartist, [hit_artist]) ≥ 0.6`.
   Артист неизвестен — достаточно фильтра 1.

Первый из top-3, прошедший фильтры, побеждает. Порог 0.6 — константа модуля
(`_FUZZY_TITLE_MIN = 0.6`), чтобы тюнить в одном месте.

Существующие юнит-тесты `tests/unit/test_playlist_resolver.py` дополняются
кейсами: (а) левый хит с пересечением в одно слово — теперь `none`;
(б) правильный трек с опечаткой/транслитом — по-прежнему `fuzzy`;
(в) верное название, но чужой артист при заданном `qartist` — `none`.

## Порядок работ и проверка

1. Резолвер (fuzzy) + тесты — изолированно.
2. Кэп веб-поисков + инструкции агента + правка тестов tools.
3. Стриминговый роут + `on_status` в `ai_playlist` (+ юнит на генератор событий).
4. Фронтенд: компонент шара + NDJSON-клиент + удаление чипсов/жёлтой строки +
   mobile/reduced-motion правила.
5. Проверка: `npm --prefix frontend run build`; юниты `tests/unit/` напрямую;
   живой прогон в Docker-стеке (запрос «Хиты Канье Уеста» — этапы должны бежать
   на шаре во время запроса, не в конце).

## Вне скоупа

- Страница в режиме `aiOn === false`, чат по треку (его шар остаётся как был),
  агентный чат-поиск (`/chat`) — не трогаем.
- Изменение старого контракта `POST /ai-playlist` — не ломаем.
